Release Notes - iOS SDK 2.2.3-rc3

Version: 2.2.3-rc3 Release date: 2026-09-22 Build number: 20260922113914

Changelog​

Added​

  • Screen brightness control via JS bridge: SET_SCREEN_BRIGHTNESS and RESTORE_SCREEN_BRIGHTNESS. Brightness is screen-scoped — the SDK captures the original level on first set and automatically restores it when the Mini App explicitly restores it, when the user leaves the Mini App screen, or when the app resigns active (re-applying the requested level when the app returns to the foreground). Values outside [0.0, 1.0] are rejected with SDK800.
  • SMS handoff via JS bridge: OPEN_SMS_COMPOSER opens the OS SMS composer with a prefilled recipient and body. The composer outcome is surfaced through the new error codes below.
  • New VDOErrorCode cases: SDK800 (brightness domain), SDK801, SDK802, SDK830, SDK840, SDK850, SDK851 (SMS handoff), SDK852 (neutral "handed off to OS" state — reports that the work was handed to the OS, not that the message was sent), and SDK100 (routing tier: "event is not routable").
  • getLocation(completion:) on VDOHostAppBridge and the public MiniAppLocation struct (latitude/longitude, WGS-84) returned by it.
  • exitMiniApp(with miniAppKey:) on VDOMiniAppSdk — programmatically close a running Mini App by its key.
  • Theme configuration API surfaced publicly: VDOMiniAppThemeConfig (with the MiniAppThemeConfig typealias kept for backward compatibility) plus the supporting enums MiniAppLeftButton, MiniAppToolbarMode, MiniAppStatusBarMode, MiniAppActionButtonThemeType, and MiniAppStatusBarForeground.
  • VDOErrorCode is now CaseIterable.
  • On-device diagnostics log overlay (internal, disabled by default): collects a timestamped log of navigation, app-state transitions, WebContent process terminations and Mini App teardown, and exposes a single floating "Share log" button in its own pass-through window. No effect on normal builds.

Changed​

  • Breaking: VDOHostAppBridge.intercept(miniAppKey:request:) now returns Bool instead of Void. The return value answers a single question — is this event the host app's to handle?

    • true = the host app owns the event; the SDK stays silent and the host app is responsible for replying exactly once via VDOMiniAppSdk.shared.sendToMiniApp(miniAppKey:data:) (the reply envelope must carry the matching request_id).
    • false = the event is unknown to the host app; the SDK returns SDK100 ("Event is not routable").

    A default implementation returning false is provided, so existing implementations only need to add return false. See the migration guide.

  • Breaking: openMiniApp(...) no longer takes navigationBarConfig: / shouldShowStatusBar:; header/status-bar appearance is now driven by themeConfig: VDOMiniAppThemeConfig?.

  • Release xcframework is now built with optimizations enabled (-O).

Removed​

  • Breaking: phone-call JS bridge events removed entirely — REQUEST_PHONE_CALL_PERMISSION, CHECK_PHONE_CALL_PERMISSION, and OPEN_PHONE_CALL. This is an intentional contract break agreed by the product owner; the web event catalog goes from 58 to 56 entries.
  • Breaking: VDONavigationBarConfig struct removed (superseded by VDOMiniAppThemeConfig).
  • Breaking: setBackgroundStatusBarColor(color:) and setBackgroundNavigationBarColor(color:) removed from VDOHostAppBridge (superseded by the theme configuration API).

Fixed​

  • JS bridge lifecycle event HOST_APP_ON_BACKGROUND was misspelled HOST_APP_ON_BACKGROUNSD; the event name is now emitted correctly.
  • White screen after a system alert (carrier USSD / OTP prompt) or keyboard change: keyboard handling now ignores events while the app is not active or when the first responder is outside the Mini App, and clamps the WebView overlap to at most 70% of the view height so the WebView never collapses to zero height.
  • WebContent process termination (memory pressure) now recovers automatically by reloading the page once the app returns to the foreground, capped at 3 reload attempts to avoid an infinite reload loop.
  • Navigation decision handler is now guarded to be invoked exactly once, preventing WebKit NSInternalInconsistencyException crashes when a decision branch is missed or fired twice.
  • WebView teardown (removeResource) now stops in-flight navigation and detaches the navigation delegate before releasing dependencies, avoiding a crash from a pending navigation callback.
